# 구현 방식과 판단

## 1. 셀 단위 상태 관리

`CollageCanvas`가 전체 레이아웃과 입력 이벤트를 관리하고, 각 `GridCell`은 자신의 좌표와 이미지 상태를 관리합니다.

```text
source_image      파일에서 처음 읽은 원본
base_image        확정된 필터 결과와 밝기 계산의 기준
cv_image          현재 화면과 출력에 사용하는 결과
tk_image          Tkinter 표시용 변환 이미지
history           이전 base_image·brightness_val 스냅샷
```

셀별로 상태를 분리했기 때문에 한 사진의 필터와 Undo가 다른 사진을 변경하지 않습니다. History Stack은 메모리 사용량이 계속 늘지 않도록 최근 10개 상태만 보존합니다.

## 2. 파괴적 편집과 비파괴 밝기 조절

반전·필터·스티커는 결과를 새 기준 이미지로 확정하는 파괴적 편집입니다. 적용 직전에 기존 상태를 History Stack에 저장합니다.

밝기는 슬라이더가 움직일 때마다 이전 결과에 값을 누적하지 않습니다. `base_image`에서 다시 계산해 밝기 값을 여러 번 변경해도 화질 손실과 값 누적을 줄였습니다.

## 3. 스티커 좌표와 Alpha blending

사용자가 누른 캔버스 좌표를 선택한 셀의 상대 좌표로 변환합니다. 스티커가 셀 경계를 넘어가면 배경과 스티커를 같은 범위로 잘라 배열 크기를 맞춥니다.

RGBA 스티커의 Alpha 채널은 다음 방식으로 각 BGR 채널과 합성합니다.

```text
result = alpha × sticker + (1 - alpha) × background
```

Alpha 채널이 없는 이미지는 잘라낸 영역에 그대로 배치합니다.

## 4. 비율 유지 resize와 crop

이미지를 셀 크기에 강제로 찌그러뜨리지 않도록 원본과 목표 영역의 가로세로 비율을 비교합니다. 목표 영역을 완전히 채울 수 있는 크기로 확대한 뒤 중앙을 잘라냅니다.

## 5. 최종 이미지 출력

화면을 캡처해서 저장하지 않습니다. 각 셀의 `cv_image`를 흰색 NumPy 배열의 해당 좌표에 배치해 최종 이미지를 재구성합니다. 화면 위 선택 테두리 같은 GUI 요소가 저장 결과에 포함되지 않습니다.

## 현재 한계

- 레이아웃은 `2x2`와 `1+2` 두 종류로 고정되어 있습니다.
- Undo가 전체 이미지 배열을 복사하므로 큰 이미지에서는 메모리 사용량이 증가합니다.
- 스티커 크기와 회전을 사용자가 조절하는 기능은 없습니다.
- 자동화된 단위 테스트와 다양한 운영체제 실행 검증이 없습니다.
- 스티커 검색 경로가 실행 위치 기준 상대 경로입니다.

다음 개선에서는 명령 패턴 기반 Undo, 레이아웃 설정 데이터 분리, 스티커 크기·회전 조절, 영상 처리 함수 테스트를 우선할 수 있습니다.
